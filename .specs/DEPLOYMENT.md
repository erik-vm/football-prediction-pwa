## Configuration Files

### 1. Dockerfile (Backend)
**Location**: `Dockerfile` (repository root)

Multi-stage Docker build for .NET 9 backend:
- Build stage: Uses SDK image
- Runtime stage: Uses ASP.NET runtime (smaller)
- Exposes port 8080 (Render requirement)

### 2. render.yaml (Backend Infrastructure)
**Location**: `render.yaml` (repository root)

Infrastructure as code for Render deployment:
- Web service configuration
- Database configuration
- Environment variables
- Auto-deployment on git push

### 3. vercel.json (Frontend Configuration)
**Location**: `vercel.json` (repository root)

Vercel deployment settings:
- Build command
- Output directory: `frontend/dist/frontend/browser` (Angular 19)
- SPA routing with negative lookahead pattern
- Serves static assets directly

### 4. .nvmrc (Node Version)
**Location**: `frontend/.nvmrc`

Specifies Node.js version 20.11.0 for Vercel builds.

## Database Migrations

### Production Database

**IMPORTANT**: Always test migrations locally first!

1. **Create Migration Locally**
   ```bash
   cd backend/src/FootballPrediction.Infrastructure
   dotnet ef migrations add MigrationName --startup-project ../FootballPrediction.Api
   ```

2. **Test Migration Locally**
   ```bash
   dotnet ef database update --startup-project ../FootballPrediction.Api
   ```

3. **Commit & Push**
   ```bash
   git add .
   git commit -m "feat: add database migration"
   git push
   ```

4. **Migration Auto-Applies**
   - Backend startup code runs `context.Database.MigrateAsync()`
   - Production database updates automatically

### Manual Migration (If Needed)

Connect to Render PostgreSQL:
```bash
# Get connection string from Render dashboard
psql <connection-string>

# Run SQL commands manually
```

## Troubleshooting

### Frontend Issues

**Problem**: Routes return 404
- **Check**: `vercel.json` rewrite rules
- **Solution**: Ensure negative lookahead pattern is correct

**Problem**: PWA not installable
- **Check**: Manifest and service worker accessible
- **Solution**: Verify rewrites don't block `.webmanifest` and `.js` files

**Problem**: Build fails
- **Check**: Node version in `.nvmrc`
- **Solution**: Match local Node version with Vercel

### Backend Issues

**Problem**: Database connection fails
- **Check**: `DATABASE_URL` environment variable
- **Solution**: Verify Render database is linked

**Problem**: Service sleeps after inactivity
- **This is normal**: Free tier sleeps after 15 minutes
- **Solution**: Use UptimeRobot for keep-alive pings

**Problem**: Background jobs not running
- **Check**: Logs for job startup messages
- **Solution**: Verify `BackgroundJobs__MatchSyncIntervalHours` is set

## Scaling

### When to Upgrade from Free Tier

**Frontend (Vercel)**:
- Exceeding 100GB bandwidth/month
- Need preview deployments for all branches
- Want faster build times

**Backend (Render)**:
- Need always-on service (no sleep)
- Exceeding memory limits
- Need multiple instances

**Database (Render)**:
- Exceeding storage limit
- Need longer backup retention
- 90-day expiration approaching

### Upgrade Paths

| Service | Free → Paid | Cost Increase |
|---------|-------------|---------------|
| Vercel Pro | More bandwidth, deployments | +$20/month |
| Render Hobby | Always-on, 512MB RAM | +$7/month |
| Render PostgreSQL Starter | 1GB storage, persistent | +$7/month |

## Performance Optimization

### Frontend

1. **Bundle Size**
   - Current: ~500KB (gzipped)
   - Target: < 300KB
   - Use code splitting and lazy loading

2. **Caching**
   - Service worker caches static assets
   - API responses cached (1 hour freshness)
   - Vercel CDN caching

3. **Loading Times**
   - First load: < 2 seconds
   - Subsequent loads: < 500ms

### Backend

1. **Response Times**
   - Average: < 100ms (warm)
   - Cold start: ~30 seconds
   - Target: < 50ms (requires caching)

2. **Database Queries**
   - Use indexes on frequently queried fields
   - Implement query result caching
   - Use connection pooling
